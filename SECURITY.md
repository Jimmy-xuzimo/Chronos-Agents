# Reporting security issues

Do not publish working tokens, pairing codes, cookies, private keys, device
payloads, or authenticated management screenshots in public issues.

Use the repository's private vulnerability reporting channel when enabled.
If it is unavailable, open a minimal issue requesting a private reporting
channel without exploit details or private data. Do not assume a response SLA.

This preview is intended for personal deployments. Run management interfaces
on loopback or authenticated HTTPS behind your own access controls. See
[the security model](docs/SECURITY.md) before exposing a Hub.
