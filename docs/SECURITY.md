# 安全模型

## 身份隔离

管理网页采用服务地址隔离的会话 Cookie（HttpOnly、SameSite=Strict；HTTPS 时 Secure），CSRF 随机值和精确 Origin。Host 校验防止 DNS rebinding；不开放任意 CORS，不接受认证令牌查询参数。浏览器管理会话只保存在内存，重启后重新登录。

管理密码使用 Argon2id + 每密码随机盐；没有默认密码。首次凭据在受限目录单独生成，初始化成功即失效。TOTP 可选，启停与改密码要求当前密码／现有验证码，操作后撤销所有管理会话。验证码有时间窗口；本预览尚不提供恢复码，启用前务必确保能保管验证器密钥。

设备配对十分钟有效、原子消费一次。每设备独立随机写入凭据，Hub 仅保存 SHA256；客户端只在保护存储中持有明文。修改设备 ID 不能越权写入其他设备；设备令牌不能读取设备列表。轮换保留旧令牌十分钟以处理写入失败，撤销同时清除新旧凭据和待用配对码。

工作台使用另一类限定设备 ID 集合的只读凭据，不能写入或管理。设备撤销与读者撤销是不同操作：撤销上报不删除已授权读者可访问的旧数据；要停止工作台读取，需要同时撤销对应读者。

## 网络与资源限制

生产上报 HTTPS、系统 CA 或用户明确导入 CA、主机名校验、TLS 1.2+，不跟随重定向；私有 CA 不是跳过证书校验。显式开发 HTTP 只允许 loopback。远程管理要求 TLS 或明确的可信反向代理。

JSON 请求最大 256 KiB；单模块 96 KiB，嵌套深度、字符串、数组、指标名、时间与数字受限。协议版本不匹配拒绝。上报按设备限流，配对／登录按直接连接 IP 限流；限流状态容量有界。客户端尊重 Retry-After 秒数并指数退避，手动按钮也不能绕开退避。凭据失效不会无限自动重试。

进程和地址双重允许，Hub 再次过滤。配置策略只包含间隔与开关，不接受远程命令、脚本路径或任意上传目的地址。更换 Hub 必须由本地管理重新配对。

## 存储与部署责任

Hub 数据库包含私人监控数据，不是匿名公开数据；服务用户目录 0700，文件 0600。Windows ACL 继承当前用户目录，Go 的 Unix 权限位不能替代 Windows ACL。备份、快照、宿主管理员权限、磁盘加密和服务器防火墙属于部署者责任。

Docker 默认非 root、丢弃 capabilities、只读根、no-new-privileges；数据目录单独持久化。不能宣称只读 docker.sock 安全：本项目根本不挂载它。Linux mount 本身可能暴露可读宿主数据，只应挂载明确需要的卷。

## 已知边界

- 管理密码单账号，面向个人／小规模设备；不提供多租户 RBAC。
- 内存会话不跨进程；不支持无状态多副本部署。
- 无远程证明：失陷设备可以伪造自身指标。
- 自带 TLS 证书更新需要重启；公钥固定、mTLS、企业 SSO 尚未提供。
- 未做第三方渗透测试；单元测试不能代替安全审计。
- Windows 商业签名和 macOS 公证需要发行方证书，预览不冒称已签名。
